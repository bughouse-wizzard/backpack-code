Your Mac keeps working
while it's shut in a bag.

Five launchd agents that stop the lid from meaning "sleep" - so the machine stays awake, quiet, cool and reachable from your phone.

macOS assumes a closed lid is a sleeping machine. Wanting the opposite means fighting a handful of details that are not in any manual. This is the result of that fight: six shell scripts, no dependencies beyond what ships with macOS.

What it does

Each piece is a small script plus a launchd agent. They watch each other, so both have to die at once for the rig to stay down.

sleep-toggle.sh

Arms and releases sleep prevention. Bind it to a hotkey - the point is one keystroke before the laptop goes in the bag.

backpack-mode.sh

Every 30s: if the lid is closed and sleep is disabled, SIGSTOPs the heavy apps and turns the panel off. Nothing is killed; SIGCONT resumes it exactly where it was.

battery-watch.sh

Pushes battery warnings to your phone at 30/20/10/5% over ntfy or Telegram, getting louder as the charge falls.

backpack-health.sh

Every 30 min: checks the other agents, restarts the dead ones, and tells you on the phone what broke and whether it healed.

sleep-audit.sh

Answers the only question that matters after a bad night: did it sleep, and what was holding it awake?

claude-rc (optional)

Keeps Claude Code's remote control alive under launchd - the reason this rig exists: driving a coding agent from the phone with the laptop shut.

Install

The installer renders the agent plists for your user, generates a private notification topic, installs a narrow sudoers rule so the sleep toggle needs no password, and loads everything. Re-running it is safe.

git clone https://github.com/bughouse-wizzard/backpack-code
cd backpack-code
./install.sh
Then add your VPN client to NEVER_FREEZE in ~/.config/backpack-mode.conf. A frozen VPN behind a closed lid cannot be fixed: you have lost the connection to the machine and nobody is there to wake it.

Removal thaws anything still frozen and restores normal sleep first: ./uninstall.sh.

It tells you what it's doing

Four of the scripts push to your phone through ntfy (or Telegram). The topic name is the entire secret, so the installer generates a long random one and keeps the config at mode 600.

The gotchas

The scripts are short. The knowledge in them is not - this is the part that cost the time.

Clamshell detection is only AppleClamshellState from ioreg.

The powerd assertion Prevent sleep while display is on is not released in clamshell mode and stays up for hours, reporting a display that is on - observed for 54 minutes. Anything keyed on it never fires.

disablesleep also disables display sleep.

Behind a closed lid the panel quietly lights an empty room. Kill it with pmset displaysleepnow, not by setting brightness to zero - that only dims.

Process lists must be blacklists, never whitelists.

A "freeze everything except what I need" rule will eventually freeze your VPN. Clients rarely look like VPNs by name, some live outside /Applications, some are system extensions. With the lid closed, that mistake is unrecoverable.

launchd gives a process 256 file descriptors. A shell gives a million.

Moving a long-running process from a terminal to launchd can drop it into a crash loop with low max file descriptors. Fix with SoftResourceLimits/NumberOfFiles. Check this when moving any process under launchd.

KeepAlive masks breakage.

A crash loop looks healthy to every "is the process running" check - there is always a process, just a new one each time. Watch the runs counter from launchctl print, or uptime. That is how 11 identical crashes in one night were found.

Write state files atomically.

Temp file plus mv, never truncate-and-append: a reader will catch the file half-written. The night logger once recorded 33 frozen processes where there were 77.
